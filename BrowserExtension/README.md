# X 直连扩展（Edge / Chromium MV3）

此扩展只在带 `#tibo-watch` 标记的两个专用页面中采集：

- `https://x.com/thsottiaux#tibo-watch`
- `https://x.com/thsottiaux/with_replies#tibo-watch`

必须保留浏览器运行和这两个页面可用。每 90 秒刷新，每 30 秒发送本地心跳；不是 X API，不保证实时、完整或持续可用。折叠正文被明确标记为不完整，不将其当作确定公告。引用内容与作者正文分别采集，引用别人的“reset”不会自动当作 Tibo 已完成重置。

## 安装

1. `./scripts/build.sh`。
2. 经用户明确同意浏览器权限后执行 `./scripts/install-x-bridge.sh`，注册本机桥接。
3. Edge 打开 `edge://extensions`，开启开发人员模式，选择“加载解压缩的扩展”，选择本目录。
4. 若专用页面出现登录要求，由用户在 X 官方页面登录。遇到验证码或限制须停下人工处理，不自动绕过。
5. 打开 Tibo Watch，确认“X 直连正常（主页＋回复）”。扩展工具栏面板也会显示连接状态，提供暂停开关和立即检查。

浏览器提示的站点权限覆盖 `x.com`，内容脚本和后台校验仅接收上述两个专用路径的快照。没有 `cookies`、浏览历史、私信或通用网页注入权限。代码不读取登录令牌、密码，也不向远程服务发送帖子；公开帖子的正文、引用文本、时间、链接和完整性标记通过 Native Messaging 传入本机应用。X 的自动化规则对非 API 页面脚本有约束，此模式不享有官方 API 的稳定性保证，也可能受到限制；遇到登录、验证、限流或页面结构变化时降级。

## 本机桥接

- 扩展固定 ID 见 identity.json；manifest.json 中只包含公开扩展密钥，不包含私钥。
- 注册主机名 `local.tibowatch.x`，只允许该扩展 ID 调用。
- Native Messaging 通过 stdin/stdout 长度帧传递数据，没有开放 localhost HTTP 端口。
- 桥接程序只写 `~/Library/Application Support/TiboWatch/x-direct-posts.json` 和 `x-direct-replies.json`。
- 拒绝非 Tibo 原帖 URL、私信路径、过大消息和非法时间戳。协议测试使用单独临时目录，不覆盖真实采集。
- 应用若 180 秒没有心跳、页面加载时间超过 240 秒或任一专用页面异常，会明确标记直连降级，并继续第三方兜底。

## 预测能力边界

这是一套本地规则驱动的信号分级，并非经过准确率回测或概率校准的语义预测模型，不调用 Codex 或云端 LLM。它不能理解所有梗或承诺必然预测重置。

- 明确将来重置语句 → 明确预告；只有可解析时间才报北京时间。
- Day N 活动里的 cooked/cooking 双关、重置按钮玩笑、有条件“交付或重置” → 低把握线索，显示证据、其他可能解释和“无法确定几点”。
- 已发生的 “and reset / done / processed” → 结果记录，默认不弹出完成通知。
- 否认重置、引用他人公告、普通产品更新不能升级为确定预告；折叠内容只作待核实线索。
- 同一 Day N 后来出现完成公告时，将旧预测归档，不再把旧梗当作当前预警。

对昨天案例的处理：只给最初的 “We're cooked” 及其当时的产品发布引用，分类为低把握，而非已完成或确定会重置；后来那条 “and reset” 不能用于给前一条加分。此规则是在本次反馈后加入，不能宣称昨天实盘预测命中。
